# Форматы и совместимость Forge3D

В 1.5.0-beta.5 статическая модель может содержать дополнительные меши по расстоянию. Проекты без таких полей используют исходную геометрию при любой дистанции. Дополнительные меши не меняют параметры физики.

В 1.5.0-beta.4 настройки света могут включать освещение небом и два профиля теней. Старые сцены загружаются с выключенным освещением небом, картой Desktop 1024 × 1024 и прежней дальностью теней.

В 1.5.0-beta.3 части моделей могут хранить карту нормалей с тангентами. Объект может переопределять её интенсивность. В проектах без новых полей сохраняется прежнее освещение.

В 1.5.0-beta.2 добавлено необязательное поле `animation_blend` в секундах. При отсутствии поля клипы переключаются мгновенно. Промежуточная поза перехода живёт только во время игры.

В 1.5.0-beta.1 добавлены необязательные поля меток клипа и переопределений объекта. Старые проекты без меток открываются с пустым списком событий. Rhai получает новый вид `animation` в существующем обработчике `on_event`.

В 1.4.2 схемы полей описаны в Rust. Формат карты `components` сохраняется, включая числовой радиус жетона и строковое имя префаба. При открытии проекта неизвестные компоненты остаются в карте.

В 1.4.1 компонент `RelayGate` хранится в карте `components`. Его поля — `role` (значения `transmitter` и `exit`) и `destination` (ID сцены для выхода). Play и экспорт проверяют ссылку и наличие триггера. В ранее сохранённых проектах Cloud Relay продолжает работать исходный Rhai-скрипт.

| Поверхность | Версия | Назначение |
| --- | --- | --- |
| Движок | 1.5.0 | Версия Forge3D, редактора, CLI и MCP-сервера |
| Сцена `.forge.json` | 2 | Сцена с настройками приложения и встроенными ресурсами |
| Проект `.forge-project.json` | 1 | Манифест со стартовой сценой, ресурсами и префабами |
| Сохранение прогресса | 1 | ID контрольной сцены и громкость |
| API скриптов Rhai | 1 | Хуки, карты объектов, камера, UI и запросы игровых действий |
| Инструменты MCP | 1 | Имена и документированные параметры и результаты инструментов Forge3D |

`forge3d-batch info` и MCP-инструмент `engine_info` возвращают эти версии в JSON. Версия протокола MCP согласуется отдельно при `initialize`. Семантическую версию вашей игры и Android `version_code` задаёт проект.

В Forge3D 1.x документированные данные и API поколения 1 сохраняют совместимость. Новые поля и инструменты могут добавляться. Внутренние Rust-модули редактора и рантайма могут меняться. Для нового несовместимого формата потребуется новое поколение и явная миграция.

## Старые проекты

- `.forge.json` схемы 1 открывается и преобразуется в схему 2. Миграция сохраняет исходный файл, а результат записывает в новый путь.
- `.forge.json` схемы 2 и манифесты проектов схемы 1 открываются напрямую. Существующие ID сохраняются.
- Чтобы сохранить доступ к прежнему прогрессу, оставьте прежний идентификатор приложения и ID контрольных сцен. Перед выпуском Android-обновления увеличьте `version_code` и используйте прежний ключ подписи.
- Ранее экспортированный Cargo-проект использует свой встроенный рантайм. Для обновления сохраните Forge3D-проект и экспортируйте его в новую папку.

```sh
forge3d-batch migrate old.forge.json migrated.forge.json
forge3d-batch project-new migrated.forge.json game.forge-project.json
forge3d-batch validate game.forge-project.json
forge3d-batch export game.forge-project.json game-source
```

## Скрипты и автоматизация

Rhai поддерживает `start(object)`, обязательный `update(object, dt, input)`, `on_event(object, event)`, `on_ui(object, event)` и `camera(view, object, dt, input)`. Сохраняются поля трансформации, `state`, управление анимацией и запросы `next_scene`, `save_scene`, `resume_game`, `play_sound`, `volume_step`. [Скрипты Rhai](docs/gameplay.md#скрипты-rhai)

Для MCP обычный маршрут проходит через `engine_info`, `project_open`, `project_validate`, `project_simulate`, `build_game`, `build_status` и `artifact_read`. Вызывайте `tools/list`, чтобы получить схемы доступных инструментов. [Руководство MCP](MCP.md)

В 1.1.1 после `start` в Rhai доступен `raycast(origin, direction, max_distance, ignore_id)`. Первые два аргумента — массивы из трёх чисел в мировых координатах. Дальность положительная и измеряется в единицах сцены. Пустая строка включает все объекты, строковый ID исключает один объект. Результат — ближайший твёрдый коллайдер с полями `object_id` (строка), `point`, `normal`, `distance`, либо `()` при промахе. Сенсоры пропускаются. Изнутри коллайдера расстояние равно нулю. В `update` доступны луч центра камеры (`input.aim_origin`, `input.aim_direction`) и строковый `object.id`. Запрос видит состояние после последнего завершённого шага физики или начальные трансформации после `start`.

В 1.2.0 `Object.components` хранит JSON по имени компонента. В коллекцию экспортированных сцен добавлено поле `prefabs`. Отсутствующие поля в прежних проектах читаются как пустые коллекции. Пользовательские компоненты обрабатываются зарегистрированным игровым модулем Rust.

1.3.0 добавляет тип тела `character` и форму `capsule`. Для персонажа нужен корневой объект с твёрдой капсулой. В массиве `size` X задаёт диаметр, Y — полную высоту. При высоте меньше диаметра капсула становится сферой. `jump_height` измеряется в единицах сцены, `max_slope_degrees` — в градусах. Прежние тела используют значения по умолчанию, движение старых кинематических объектов сохраняется.

В 1.3.1 поля привязок сцены и действие кнопки UI добавлены с совместимыми значениями по умолчанию. Старые проекты сохраняют клавиши движения. Новые привязки прыжка и взаимодействия по умолчанию — Space и E. Скрипт, который проверяет конкретную клавишу через `input.pressed`, продолжает получать исходную клавишу. Для переназначения игровой механики используйте `input.actions`.

1.4.0 добавляет необязательную связь `object.prefab` с именем префаба и ID исходного узла. Старые копии без связи сохраняют самостоятельные свойства. Применение и откат касаются свойств существующих узлов. Перестройка иерархии, положение и поворот корня не распространяются на остальные экземпляры. У сцен без `lighting.skybox` остаётся прежний однотонный фон.
