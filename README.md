# Forge3D 1.0.1

Forge3D — 3D-движок на Rust с настольным редактором сцен и экспортом игр в самостоятельные Cargo-проекты. Редактор использует Macroquad и egui. Игровой проект использует Macroquad и включает исходники рантайма.

## Запуск редактора

Установите актуальный стабильный Rust. На Windows используйте Rust MSVC и Visual Studio Build Tools с компонентами C++. На Mac с Apple Silicon установите Command Line Tools командой `xcode-select --install`. На Linux установите библиотеки разработки X11, Xi, OpenGL и ALSA (`libx11-dev libxi-dev libgl1-mesa-dev libasound2-dev` в Ubuntu). Команда ниже запускает редактор из каталога `forge3d`.

```sh
cargo run --locked
```

Редактор открывается со сценой **Light & Motion Workshop**. Нажмите **Play**, чтобы увидеть, как двухкостная рука движется и отбрасывает тень рядом с полированной и матовой сферами. В **Inspector → Animation** можно переключить клип **Sweep** на **Reach**. Сцена **Physics Workshop** доступна через **Tools → Physics demo…**.

## Первый проект

1. Откройте готовый `workshop-run.forge-project.json` через **File → Open…** или выберите **Project → Open Workshop Run…**.
2. Нажмите **Play** и начните новый забег. Пройдите оба уровня, затем вернитесь в редактор и попробуйте изменить положение объекта или подпись кнопки.
3. Сохраните проект и выберите **File → Export Rust…**. Для готовой сборки используйте **Tools → Build…**. Автономный Cargo-проект содержит сцены и исходники на Rust.

```sh
cargo run --locked --bin forge3d-batch -- campaign-demo workshop-run.forge-project.json
cargo run --locked --bin forge3d-batch -- validate workshop-run.forge-project.json
cargo run --locked --bin forge3d-batch -- export workshop-run.forge-project.json game-source
cargo run --manifest-path game-source/Cargo.toml -- --check-scene
```

Задания GitHub Actions упаковывают Forge3D, CLI, MCP и стартовый проект для Windows x64, macOS arm64 и Linux x64. В скачанном артефакте распакуйте `forge3d-editor-*.tar.gz`. В пакете macOS распакуйте также `Forge3D.app.zip`. Подпись и нотарификация macOS выполняются отдельно.

## Работа со сценой

- **Hierarchy** содержит объекты сцены. Добавляйте примитивы или выбирайте объекты в списке и в 3D-окне. В **Inspector** доступны позиция, углы поворота, масштаб, видимость и параметры поведения.
- Правой кнопкой мыши вращайте камеру редактора, средней перемещайте её, колёсиком меняйте расстояние. **Frame** центрирует выбранный объект. Перетаскивайте цветную метку оси в 3D-окне, чтобы перемещать объект. **Scene settings** открывает параметры камеры, используемой в игре.
- **File → Import model…** принимает путь к OBJ, FBX, glTF или GLB. Поддерживаются статические треугольные меши, базовый цвет и цветовые текстуры. Для OBJ расположите MTL и его PNG/JPEG-текстуры рядом с исходной моделью или сохраните их относительные пути. Для glTF оставьте внешние ресурсы по путям, указанным в файле.
- Вкладка **Assets** позволяет создавать экземпляры уже импортированных моделей. **Save…** сохраняет сцену со всеми импортированными ресурсами в один файл `.forge.json`. Относительные пути в окнах ввода отсчитываются от рабочего каталога редактора.

Объекты имеют постоянные ID. Выберите родителя в раскрывающемся списке **Inspector**. Иерархия отображается с отступами, дочерние объекты наследуют трансформацию и видимость родителя. При переподчинении сохраняются локальные координаты. **Undo** и **Redo** доступны на панели инструментов и через Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z. Удаление поддерева тоже можно отменить.

### FBX

На вкладке **Project** откройте `example.fbx` из пакета редактора или импортируйте свою модель через **File → Import model…**. Поддерживаются ASCII и бинарные FBX, триангуляция полигонов, преобразования узлов, UV, нормали, базовые материалы и встроенные или внешние текстуры PNG/JPEG. Геометрия приводится к метрам и оси Y вверх. Для внешних текстур сохраните относительные пути или положите файлы рядом с FBX. Результат сохраняется в проекте и экспортируется в Rust вместе с текстурами.

FBX в 1.0.1 импортируется как статический меш. Для скелета и анимационных клипов используйте glTF/GLB.

### Рабочая область и горячие клавиши

Иерархия слева поддерживает сворачивание веток. Инспектор справа редактирует выбранный объект. В нижней панели вкладки **Project**, **Assets** и **Console** разделяют файлы, импортированные ресурсы и сообщения. Панели можно менять местами и масштабировать через **Workspace → UI scale**. Верхняя панель переключает **Scene** и **Game**, запускает предпросмотр, ставит его на паузу и выполняет один кадр.

| Клавиши | Действие |
| --- | --- |
| Ctrl/Cmd+N, O | Новая сцена, открыть файл |
| Ctrl/Cmd+S, Shift+Ctrl/Cmd+S | Сохранить, сохранить как |
| Ctrl/Cmd+I | Импортировать модель |
| Ctrl/Cmd+Z, Shift+Ctrl/Cmd+Z | Отменить, повторить |
| Ctrl/Cmd+D, Delete | Дублировать или удалить объект вместе с потомками |
| Q, W, E, R | Выбор, перемещение, поворот, масштаб |
| F | Приблизить выбранный объект |
| F5, F6, F7 | Play/Stop, Pause/Resume, один кадр на паузе |
| Esc | Закрыть диалог |
| Ctrl/Cmd + «+», «−» или «0» | Изменить масштаб редактора или вернуть 125% |

Подсказки доступны в **Help**. Клавиши инструментов сцены отключаются во время ввода текста и в режиме игры. Ctrl/Cmd+S сохраняет проект и при редактировании текста.

В меню **Tools** доступны **Test scene**, **Capture PNG** и **Build**. Тест прогоняет 60 кадров и показывает ошибки Rhai. Захват сохраняет программный предпросмотр игровой камеры. Текущий этап фоновой сборки виден в строке состояния. **Console** показывает результат, журнал и пути к артефактам. В меню **Tools** можно выбрать **Cancel build** или **Retry build…**. Повтор использует снимок исходной сцены и тот же профиль, а результат записывает в новую папку. Для Android нужен настроенный инструментарий, перечисленный в README экспортированного проекта.

## Проекты, сцены и префабы

В редакторе выберите **Project → Create from current scene…**, чтобы перенести текущую сцену в проект, или откройте готовый пример через **Project → Open two-scene demo…**. **Add scene…** добавляет пустую сцену или импортирует существующий файл `.forge.json`. **Edit scene** сохраняет рабочие изменения в открытом проекте и переключает сцену. Нажмите **Save project…**, чтобы записать все сцены на диск.

Манифест `.forge-project.json` хранит сцены, модели, скрипты и префабы вместе. Одинаковые модели и общие скрипты переиспользуют записи с постоянными ID. **Shared assets** добавляет модель или скрипт из библиотеки в активную сцену. **Create prefab from selection…** сохраняет выбранный объект и его потомков. **Insert prefab** создаёт редактируемую копию с новыми ID объектов и сохраняет связи внутри иерархии.

**Use active scene at launch** задаёт стартовую сцену экспорта и сборки. Настройки окна и приложения берутся из стартовой сцены. **Play** в редакторе начинает с открытой сцены, чтобы её можно было проверить независимо от точки входа игры.

Rhai может запросить переход, вернув `object.next_scene` со строковым ID сцены из `start`, `update` или `on_event`. После перехода объекты, физика и состояние скриптов загружаются из сохранённой сцены. В демонстрации нажмите **D** или стрелку вправо, чтобы попасть в мастерскую, затем **A** или стрелку влево для возврата. На Android используйте экранные стрелки.

```sh
cargo run --locked --bin forge3d-batch -- project-demo demo.forge-project.json
cargo run --locked --bin forge3d-batch -- project-list demo.forge-project.json
cargo run --locked --bin forge3d-batch -- project-start demo.forge-project.json workshop
cargo run --locked --bin forge3d-batch -- export demo.forge-project.json game-source
```

Чтобы перенести свой проект, начните с `project-new OLD.forge.json NEW.forge-project.json` и добавьте сцены командой `project-add PROJECT SCENE_ID SCENE.forge.json`. Команды `export` и `build` принимают как файлы сцен, так и манифесты проектов.

## Меню, игровой UI и сохранение

Откройте **Project → Open Workshop Run…** и нажмите **Play**. В игре **Enter** начинает новый забег, **C** продолжает с контрольной точки, **−** и **=** меняют громкость. В первом уровне двигайтесь вправо. Во втором сдвиньте розовую сферу влево. На Android доступны экранные стрелки и кнопки меню. `campaign-demo` в CLI или MCP создаёт тот же пример.

**Tools → Game UI and audio…** редактирует определения активной сцены. Координаты `rect` задают левый край, верх, ширину и высоту от 0 до 1. Варианты `kind` — `text`, `image` и `button`. В кнопках задайте уникальный `id` и, при необходимости, `key` со значением `enter`, `escape`, `space`, `c`, `minus` или `equal`. Изображения хранят байты PNG в `png`. В `sounds` ключ — ID звука, значение — байты 16-битного PCM WAV. В тексте `{volume}` отображает громкость в процентах, а `{checkpoint}` — сохранённый ID контрольной сцены.

```rhai
fn update(object, dt, input) { object }

fn on_ui(object, event) {
    if event.id == "start" {
        object.next_scene = "entrance";
        object.save_scene = "entrance";
        object.play_sound = "cue";
    }
    object
}
```

Верните `object.resume_game = true` для загрузки сохранённой сцены и `object.volume_step = 0.1` для изменения громкости. Прогресс сохраняет ID контрольной сцены и громкость. После возобновления физика и локальное состояние объектов создаются заново. Экспортированная игра пишет сохранение в каталог данных приложения, на Android использует закрытый каталог приложения. Просмотр в редакторе и симуляция MCP используют прогресс в памяти.

В CLI команда `project-ui PROJECT SCENE_ID UI_JSON` загружает определения из JSON. Чтобы экспортировать пример, выполните:

```sh
cargo run --locked --bin forge3d-batch -- campaign-demo workshop-run.forge-project.json
cargo run --locked --bin forge3d-batch -- export workshop-run.forge-project.json game-source
```

## Освещение, материалы и анимация

В **Scene settings → Lighting** задайте цвет и направление солнца, интенсивность, фоновое освещение и размер области теней. Для локального света добавьте **Point light** в инспекторе объекта. Рендер учитывает четыре ближайших к камере точечных источника. Тени от солнца строятся по карте глубины 1024×1024. Объекты могут отключить отбрасывание тени через **Cast shadows**.

PBR-рендер использует модель metallic–roughness с прямым светом. Импорт glTF и GLB сохраняет базовый цвет, metallic, roughness, emissive, цветовую текстуру и карты metallic–roughness и emissive, использующие ту же UV-развёртку. **Material and light** позволяет переопределить значения на конкретном объекте. Карты нормалей, освещение от окружения и морф-цели остаются вне этого релиза.

Для анимации поддерживаются преобразования узлов, скелетное смешивание до четырёх весов на вершину и ключи STEP, LINEAR и CUBICSPLINE. При добавлении модели редактор выбирает её первый клип. В **Animation** можно переключить клип, задать стартовое время, паузу, повтор и скорость, в том числе обратное воспроизведение. PNG через MCP показывает заданную позу с упрощённым программным освещением.

## Физика, события и ввод

В **Inspector → Physics** добавьте тело и выберите **Box** или **Sphere**. Размер задаётся до применения масштаба объекта. У сферы используется диаметр из первого поля и наибольшая ось масштаба. В меню **Workspace** можно показывать границы коллайдеров. Янтарные контуры обозначают триггеры.

| Тип тела | Поведение |
| --- | --- |
| **Static** | Пол, стены и неподвижные препятствия |
| **Dynamic** | Реакция на гравитацию и столкновения. Размещается в корне сцены. |
| **Kinematic** | Положение задаётся движением или скриптом. Подходит для двигающихся платформ и датчиков. |

**Trigger (sensor)** отслеживает пересечения, позволяя телам двигаться сквозь него. Симуляция Rapier использует фиксированный шаг 60 Гц и запускается на копии сцены. У динамического тела **Movement** управляет горизонтальной скоростью. Прямое изменение координат из Rhai перемещает тело в указанную точку. На телах доступны трение, упругость, множитель гравитации и блокировка вращения.

В **Scene settings** настройте гравитацию и клавиши движения. Сенсорные кнопки Android посылают те же оси ввода. Выберите объект в **Camera script**, чтобы его Rhai-функция управляла игровой камерой.

## Скриптинг на Rhai

Выберите объект, в **Inspector → Script · Rhai** нажмите **Attach inline script** и отредактируйте встроенный пример. **Check script** проверяет синтаксис и сигнатуры. **Play** запускает скрипты на копии сцены, а **Stop** сбрасывает изменения и состояние.

```rhai
fn start(object) {
    object.state.speed = 2.0;
    object
}

fn update(object, dt, input) {
    object.x += input.x * object.state.speed * dt;
    object.z += input.z * object.state.speed * dt;
    object.ry = (object.ry + 70.0 * dt) % 360.0;
    object
}
```

| Поле | Значение |
| --- | --- |
| `object.x/y/z` | Позиция |
| `object.rx/ry/rz` | Углы поворота в градусах |
| `object.sx/sy/sz` | Масштаб по осям |
| `object.visible` | Видимость, `true` или `false` |
| `object.state` | Карта данных объекта, сохраняемая между кадрами |
| `dt` | Время в секундах. В сценах с физикой передаётся шаг 1/60. |
| `input.x/z` | Оси назначенных клавиш и экранных кнопок Android |

`start(object)` вызывается один раз и необязателен. `update(object, dt, input)` вызывается после встроенных Spin и Movement на каждом кадре. Обе функции возвращают карту `object`. Помещайте исполняемый код внутрь функций. Ошибка выполнения отключает скрипт этого объекта до следующего запуска и отображается в строке состояния редактора или в журнале игры.

В дополнение к `update` скрипт может реализовать `on_event(object, event)`. Обработчик вызывается на обоих объектах после шага физики и возвращает `object`. Доступны `event.kind` со значениями `collision_enter`, `collision_exit`, `trigger_enter`, `trigger_exit`, строковый ID `event.other_id` и имя `event.other_name`. События видны в **Console**.

Выбранный контроллер камеры может реализовать `camera(view, object, dt, input)`, которая вызывается после обработки событий и возвращает `view`. В карте `view` есть цель `x/y/z`, углы `yaw/pitch` в градусах и `distance`. Координаты `object` локальны относительно родителя.

Rhai на анимируемой модели получает поля `anim_clip`, `anim_time`, `anim_speed`, `anim_playing` и `anim_loop`. Например, чтобы замереть в позе, присвойте `object.anim_time = 0.6` и `object.anim_playing = false`. Пустой `anim_clip` возвращает модель в исходную позу. При смене клипа время сбрасывается, если скрипт его сам не изменил.

Кнопка **Import .rhai…** в **Assets** загружает общий скрипт. Выберите его в инспекторе нужных объектов. Изменение общего исходника применяется ко всем его экземплярам. Каждый объект хранит своё игровое состояние. **Console** показывает ошибки компиляции и выполнения.

Исходники встроенных и общих скриптов хранятся в сцене и вместе с ней попадают в экспорт. В экспортированном проекте его можно менять через `assets/scene.json`, а исходники рантайма и обработчика скриптов доступны в `src/`.

## Экспорт, сборки и распространение

Откройте **Tools → Application settings…**, чтобы задать имя приложения, идентификатор в обратном DNS-формате, семантическую версию и код версии Android. Там же настраиваются размеры и режим окна настольной игры, а также ориентация и полноэкранный режим Android. **File → Export Rust…** создаёт самостоятельный Cargo-проект. Для фоновой сборки откройте **Tools → Build…** и выберите профиль и новую папку.

| Профиль | Результат |
| --- | --- |
| **Check / Test** | Проверка компиляции или тесты Cargo |
| **Debug** | Исполняемый файл в каталоге `target` |
| **Release** | Исполняемый файл Windows или Linux либо архив `.app.zip` для macOS в каталоге `dist` |
| **APK debug** | APK ARM64 с отладочной подписью |
| **APK release / AAB release** | APK либо Android App Bundle ARM64 с указанным ключом релиза |

Для Cargo-профилей доступны системная цель и явные цели Windows x64 (MSVC), macOS Apple Silicon и Linux x64. Для нативной сборки используйте соответствующую ОС и установленный инструментарий. Настольный архив macOS содержит метаданные `.app`. Подпись Developer ID и нотарификация выполняются внешними инструментами Apple.

### Подпись Android

Перед запуском редактора, сервера MCP или Gradle задайте четыре переменные окружения. Укажите путь к существующему ключу и его параметры.

| Переменная | Значение |
| --- | --- |
| `FORGE3D_ANDROID_KEYSTORE` | Абсолютный путь к файлу хранилища ключей |
| `FORGE3D_ANDROID_KEY_ALIAS` | Псевдоним ключа |
| `FORGE3D_ANDROID_STORE_PASSWORD` | Пароль хранилища |
| `FORGE3D_ANDROID_KEY_PASSWORD` | Пароль ключа |

Ключи и пароли хранятся в окружении процесса сборки. Для автоматизации используйте защищённые переменные CI. Профили релиза требуют полный набор параметров. Тестовый APK из релиза движка подписан отдельным демонстрационным ключом.

### CLI и миграция сцен

```sh
cargo run --locked --bin forge3d-batch -- migrate old.forge.json new.forge.json
cargo run --locked --bin forge3d-batch -- export new.forge.json game-source
cargo run --locked --bin forge3d-batch -- build new.forge.json game-build release
cargo run --locked --bin forge3d-batch -- retry game-build game-build-retry
```

Beta открывает сцены alpha версии 1 и обновляет их до схемы 2 в памяти. Миграция сохраняет объекты, ресурсы и настройки сцены. Команда `migrate` записывает новую копию. При прерванной записи до публикации файла можно снова открыть последнее сохранение. Экспорт публикует папку после записи всех файлов.

CLI пишет этапы в stderr и итоговый JSON в stdout. Нажмите Ctrl+C, чтобы остановить сборку и её дочерние процессы. `retry` читает снимок сцены и профиль из подготовленного каталога. При сбое до создания каталога запустите `build` с исходной сценой.

GitHub Actions содержит матрицу Windows x64, macOS 15 arm64, Linux и Android ARM64. В задании macOS проверяется архитектура раннера. Настольные задания собирают игру и запускают `--check-scene`. Флаг `--window-smoke` открывает настоящее игровое окно, рисует восемь кадров и завершает процесс. В CI он выполняется на Linux, а для Windows и macOS его можно включить при ручном запуске матрицы. Android-задание устанавливает `libasound2-dev` для Linux-версии `forge3d-batch`, собирает APK и AAB и проверяет подписи, используя отдельный ключ запуска CI. ## Замер производительности

Из папки экспортированной игры соберите оптимизированный бинарный файл и запустите замер выбранной сцены.

```sh
cargo build --release
./target/release/forge-game --benchmark 180 workshop > benchmark.json
```

На Windows используйте `forge-game.exe`. Второй аргумент команды выбирает сцену. Если его опустить, используется стартовая сцена проекта. Замер ждёт 30 кадров прогрева, затем выводит JSON с временем разбора сцен, временем до первого кадра, p50 и p95 времени кадра, временем подготовки кадра на CPU и пиковой резидентной памятью процесса. Замер запускается без пользовательского ввода и сохранений. Для сравнения используйте одну сборку, сцену, размер окна и графический режим. В Linux-задании CI отчёт сохраняется как артефакт.

## Автоматизация через MCP

Соберите `forge3d-mcp`, чтобы агент мог использовать Forge3D без графического окна. Сервер поддерживает stdio и Streamable HTTP. Агент может редактировать и тестировать сцены, получать PNG, запускать сборки и читать готовые артефакты.
