## Сборка редактора из исходников

Установите актуальный стабильный Rust. На Windows используйте Rust MSVC и Visual Studio Build Tools с компонентами C++. На Mac с Apple Silicon установите Command Line Tools командой `xcode-select --install`. На Linux установите библиотеки разработки X11, Xi, OpenGL и ALSA (`libx11-dev libxi-dev libgl1-mesa-dev libasound2-dev libudev-dev` в Ubuntu). Команда ниже запускает редактор из каталога `forge3d`.

```sh
cargo run --locked
```

Редактор открывается со сценой **Light & Motion Workshop**. Нажмите **Play**, чтобы увидеть, как двухкостная рука движется и отбрасывает тень рядом с полированной и матовой сферами. В **Inspector → Animation** можно переключить клип **Sweep** на **Reach**. Сцена **Physics Workshop** доступна через **Tools → Physics demo…**.

## Экспорт проекта

Откройте **Tools → Application settings…**, чтобы задать имя приложения, идентификатор в обратном DNS-формате, семантическую версию и код версии Android. Там же настраиваются размеры и режим окна настольной игры, а также ориентация и полноэкранный режим Android. **File → Export Rust…** создаёт самостоятельный Cargo-проект. Для фоновой сборки откройте **Tools → Build…** и выберите профиль и новую папку.

| Профиль | Результат |
| --- | --- |
| **Check / Test** | Проверка компиляции или тесты Cargo |
| **Debug** | Исполняемый файл в каталоге `target` |
| **Release** | Исполняемый файл Windows или Linux либо архив `.app.zip` для macOS в каталоге `dist` |
| **APK debug** | APK ARM64 с отладочной подписью |
| **APK release / AAB release** | APK либо Android App Bundle ARM64 с указанным ключом релиза |

Для Cargo-профилей доступны системная цель и явные цели Windows x64 (MSVC), macOS Apple Silicon и Linux x64. Для нативной сборки используйте соответствующую ОС и установленный инструментарий. Настольный архив macOS содержит метаданные `.app`. Подпись Developer ID и нотарификация выполняются внешними инструментами Apple.

### Подпись Android

Перед запуском редактора, сервера MCP или Gradle задайте четыре переменные окружения. Укажите путь к существующему ключу и его параметры.

| Переменная | Значение |
| --- | --- |
| `FORGE3D_ANDROID_KEYSTORE` | Абсолютный путь к файлу хранилища ключей |
| `FORGE3D_ANDROID_KEY_ALIAS` | Псевдоним ключа |
| `FORGE3D_ANDROID_STORE_PASSWORD` | Пароль хранилища |
| `FORGE3D_ANDROID_KEY_PASSWORD` | Пароль ключа |

Ключи и пароли хранятся в окружении процесса сборки. Для автоматизации используйте защищённые переменные CI. Профили релиза требуют полный набор параметров.

### CLI и миграция сцен

```sh
cargo run --locked --bin forge3d-batch -- migrate old.forge.json new.forge.json
cargo run --locked --bin forge3d-batch -- export new.forge.json game-source
cargo run --locked --bin forge3d-batch -- build new.forge.json game-build release
cargo run --locked --bin forge3d-batch -- retry game-build game-build-retry
```

Forge3D открывает сцены версии 1 и обновляет их до схемы 2 в памяти. Миграция сохраняет объекты, ресурсы и настройки сцены. Команда `migrate` записывает новую копию. При прерванной записи до публикации файла можно снова открыть последнее сохранение. Экспорт публикует папку после записи всех файлов.

CLI пишет этапы в stderr и итоговый JSON в stdout. Нажмите Ctrl+C, чтобы остановить сборку и её дочерние процессы. `retry` читает снимок сцены и профиль из подготовленного каталога. При сбое до создания каталога запустите `build` с исходной сценой.

GitHub Actions содержит матрицу Windows x64, macOS 15 arm64, Linux и Android ARM64. В задании macOS проверяется архитектура раннера. Настольные задания собирают игру и запускают `--check-scene`. Флаг `--window-smoke` открывает настоящее игровое окно, рисует восемь кадров и завершает процесс. В CI он выполняется на Linux, а для Windows и macOS его можно включить при ручном запуске матрицы. Android-задание устанавливает `libasound2-dev libudev-dev` для Linux-версии `forge3d-batch`, собирает APK и AAB и проверяет подписи, используя отдельный ключ запуска CI. ## Замер производительности

Из папки экспортированной игры соберите оптимизированный бинарный файл и запустите замер выбранной сцены.

```sh
cargo build --release
./target/release/forge-game --benchmark 180 workshop > benchmark.json
```

На Windows используйте `forge-game.exe`. Второй аргумент команды выбирает сцену. Если его опустить, используется стартовая сцена проекта. Замер ждёт 30 кадров прогрева, затем выводит JSON с временем разбора сцен, временем до первого кадра, p50 и p95 времени кадра, временем подготовки кадра на CPU и пиковой резидентной памятью процесса. Замер запускается без пользовательского ввода и сохранений. Для сравнения используйте одну сборку, сцену, размер окна и графический режим. В Linux-задании CI отчёт сохраняется как артефакт.
