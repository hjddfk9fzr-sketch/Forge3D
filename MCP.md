# Forge3D MCP

`forge3d-mcp` запускается без редактора и поддерживает stdio и Streamable HTTP. У каждого процесса stdio и каждой HTTP-сессии своя сцена, история правок и список сборок. MCP и редактор обмениваются сценами через файлы `.forge.json`.

## Подключение

Соберите сервер из каталога Forge3D.

```sh
cargo build --locked --release --bin forge3d-mcp
```

В примерах замените оба пути абсолютными путями к собранному файлу и каталогу игровой сцены. На Windows имя файла заканчивается на `.exe`. `--root` задаёт каталог проекта. Сцены, файлы моделей, внешние текстуры, скрипты и места сохранения должны находиться внутри него.

### Codex CLI

```sh
codex mcp add forge3d -- /path/to/forge3d-mcp --root /path/to/game-project
```

### Claude Code

```sh
claude mcp add --transport stdio forge3d -- /path/to/forge3d-mcp --root /path/to/game-project
```

### Antigravity и клиенты с конфигурацией `mcpServers`

Добавьте запись Forge3D в конфигурацию MCP клиента.

```json
{
  "mcpServers": {
    "forge3d": {
      "command": "/path/to/forge3d-mcp",
      "args": ["--root", "/path/to/game-project"]
    }
  }
}
```

### Streamable HTTP для удалённых клиентов

```sh
forge3d-mcp --root /path/to/game-project --http 127.0.0.1:7333
codex mcp add forge3d --url http://127.0.0.1:7333/mcp
```

Для подключения с другой машины укажите в клиенте HTTPS-адрес `/mcp` за прокси. Перед запуском задайте `FORGE3D_MCP_TOKEN` и настройте в клиенте заголовок `Authorization: Bearer …`. При прямом прослушивании адреса, отличного от loopback, сервер требует токен. Для клиентов, отправляющих `Origin`, установите `FORGE3D_MCP_ORIGIN` в точное значение разрешённого источника. Сессия хранится в памяти и закрывается после часа без запросов. Для проверки статуса и чтения файла используйте ту же сессию, в которой начали сборку.

## Доступные операции

| Задача | Инструменты |
| --- | --- |
| Просмотреть файлы проекта | `project_list` |
| Создать, открыть, прочитать или сохранить сцену | `scene_new`, `scene_open`, `scene_snapshot`, `scene_save`, `scene_settings`, `scene_migrate` |
| Создать и изменить объекты, перестроить иерархию | `object_create`, `object_update`, `object_duplicate`, `object_delete` |
| Импортировать модели и управлять скриптами | `import_model`, `script_check`, `script_asset_set`, `asset_remove` |
| Проверить поведение без окна и откатить правки | `simulate`, `undo`, `redo` |
| Проверить ожидаемый результат симуляции | `test_scene` |
| Получить изображение игровой камеры | `scene_capture` |
| Экспортировать и собрать игру | `export_game`, `build_game`, `build_status`, `build_cancel`, `build_retry`, `artifact_read` |

Запрашивайте `scene_snapshot` для получения постоянных ID объектов и текущих индексов ресурсов. `object_update` принимает поле `parent` с ID родителя или `null` для корня. Позиция, поворот и масштаб остаются локальными относительно нового родителя. Скрипт можно задать как `{"source":"..."}`, как ссылку `{"asset":0}` или снять через `null`.

Обычный сценарий автоматизации начинается с `scene_new` или `scene_open`. Затем агент импортирует ресурсы, создаёт объекты, прикрепляет скрипты и вызывает `simulate`. Этот инструмент выполняет до 600 кадров на временной копии сцены и возвращает трансформации и ошибки скриптов. `scene_save` сохраняет редактируемую сцену. Для перезаписи файла передайте `overwrite: true`. `export_game` создаёт новый каталог с Cargo-проектом. Команды сборки Windows, macOS и Android находятся в README этого проекта.

## Проекты с несколькими сценами

- `project_new` переносит текущую сцену в проект. `project_demo` открывает пример с двумя сценами и префабом. Используйте `project_open` и `project_save` для файлов `.forge-project.json`.
- `project_add_scene` принимает ID `scene` и необязательный `source` с путём к старой сцене. `project_select_scene` переключает активную сцену для инструментов `object_*`, `scene_settings` и `simulate`.
- `project_info` возвращает список сцен, активную и стартовую сцены, префабы и постоянные ID ресурсов. `project_use_asset` принимает `kind` и `asset_id` и возвращает локальный индекс, пригодный для `object_create` и `object_update`.
- `prefab_create` принимает `prefab` и ID корневого объекта `root`. `prefab_instantiate` копирует иерархию в текущую сцену и по желанию подвешивает её под объект `parent`. Инструмент возвращает новый ID корня.
- `project_start` выбирает стартовую сцену для `export_game` и `build_game`. `project_simulate` запускает игру со стартовой сцены и возвращает список посещённых сцен и ошибки. Укажите `input: [1, 0]` в демо, чтобы увидеть переход.
- `project_close` закрывает проект и оставляет текущую сцену открытой для обычных инструментов.

## Игровой UI, звук и прогресс

`campaign_demo` открывает Workshop Run. `presentation_get` возвращает UI и звуки активной сцены, а `presentation_set` принимает их в поле `presentation` и проверяет координаты, ID кнопок и форматы ресурсов. Для проверки игры вызовите `project_simulate` с `actions`, например `[{"frame":0,"button":"quiet"},{"frame":1,"button":"start"}]`, и `input: [1, 0]`. Ответ содержит посещённые сцены, контрольную точку, громкость и ID запрошенных звуков. Симуляция хранит прогресс в памяти, поэтому её можно запускать без изменения пользовательских сохранений.

## FBX и дублирование

`import_model` принимает ASCII и бинарные FBX как статические меши. Внешние PNG/JPEG должны находиться внутри корня проекта MCP. `instantiate: false` импортирует ресурс без добавления объекта. `object_duplicate` принимает `id` корня, возвращает `root` копии и сохраняет ссылки на существующие модели и скрипты.

## Проверки совместимости

Перед автоматизацией вызовите `engine_info`. Он возвращает версию движка и поколения форматов сцен, проектов, сохранений, API Rhai и инструментов MCP. `project_validate` проверяет требования экспорта для всех сцен, включая скрипты. Для активного проекта учитывается рабочая версия текущей сцены. Ответ содержит `valid`, число сцен и `starting_scene`.

## Тестирование, снимки и сборки

- `test_scene` возвращает `passed`, список ошибок Rhai и несовпадения с ожидаемыми локальными трансформациями или видимостью. Пример аргументов — `{"frames":60,"assertions":[{"id":1,"position":[0,0.55,0],"tolerance":0.01}]}`.
- `scene_capture` сохраняет PNG размером от 64 до 1024 пикселей по каждой оси и возвращает изображение в MCP. Вы можете указать кадр через `frames` и отключить выдачу в ответе через `inline: false`. Это программный рендер с глубиной и базовыми текстурами. Он подходит для предпросмотра без графического окна.
- `build_game` экспортирует проект в новый каталог и возвращает `job`. Профили `check`, `test`, `debug` и `release` используют Cargo на машине сервера. `android-debug` использует Gradle, Android SDK, NDK и Cargo NDK. При необходимости путь к Gradle можно задать через `FORGE3D_GRADLE`.
- `build_status` возвращает текущий этап. После завершения ответ содержит `report` с кодом причины, кодом завершения процесса, концом журналов и списком артефактов. Например, `missing_toolchain` означает, что Cargo или Gradle не удалось найти, а `android_signing` указывает на ошибку настройки или подписи Android.
- `build_cancel` принимает `job` и запрашивает остановку. Дождитесь итогового статуса через `build_status`. `build_retry` принимает завершённый `job` и путь `path` к новой папке внутри корня проекта. Возвращает новый `job` и использует исходный снимок сцены или всего проекта, профиль и целевую архитектуру.
- `artifact_read` принимает `job`, индекс файла из этого списка и смещение `offset`. Склейте декодированные блоки base64, используя `next_offset` до `eof: true`.

Для сборки Android через Linux-сервер установите `libasound2-dev` на хосте до компиляции Forge3D. Проверьте `project_simulate`, передайте профиль `android-release` в `build_game`, дождитесь `succeeded` в `build_status` и получите APK частями через `artifact_read`. Для сборки релизного APK серверу нужен ключ подписи.

## Физика и игровые события

- `scene_new {"physics_demo":true}` открывает Physics Workshop. Получите ID пола, шара, датчика и барьера из `scene_snapshot`.
- `object_update` принимает `body`. Пример тела — `{"kind":"dynamic","collider":"sphere","size":[1,1,1],"lock_rotation":true}`. Варианты `kind` — `static`, `dynamic` и `kinematic`. Установите `sensor: true` для триггера, либо передайте `body: null` для снятия тела. Дополнительные поля включают `gravity_scale`, `friction` и `restitution`.
- `scene_settings` принимает `gravity`, частичное обновление `bindings` и ID `camera_controller`. Перед назначением контроллера добавьте объекту скрипт с `camera(view, object, dt, input)`.
- `simulate` возвращает трансформации, камеру, физические события и ошибки. `test_scene` принимает `expect_events`, например `[{"kind":"trigger_enter","a":2,"b":3}]`. Порядок участников пары не влияет на проверку.

## Освещение и анимация

- `scene_new {"rendering_demo":true}` открывает Light & Motion Workshop. `scene_snapshot` возвращает список клипов каждой модели и их длительность.
- `scene_settings` принимает частичное обновление `lighting`, например `{"shadows":false,"intensity":3.0}`.
- `object_update` принимает `light` для точечного источника, `surface` для переопределения материала и `cast_shadows` для переключения тени. Для настройки клипа передайте `animation`, например `{"clip":"Reach","time":0.6,"playing":false}`. Значение `animation: null` возвращает исходную позу.
- `simulate` возвращает текущие параметры воспроизведения. `scene_capture` вычисляет позу после указанного числа кадров и сохраняет PNG с упрощённым программным освещением.

## Профили распространения

`scene_settings` принимает частичное обновление `application`, например `{"identifier":"com.studio.game","version":"1.2.0","version_code":12}`. `scene_migrate` принимает `source` и `destination` и записывает отдельную копию в текущей схеме.

`build_game` принимает `android-release` для подписанного APK и `android-bundle` для подписанного AAB. Для настольных профилей можно передать `target` со значением `windows-x64`, `macos-arm64` или `linux-x64`. Параметры подписи Android задаются в окружении MCP-сервера.
